# Contributing

Thanks for helping improve the Tsuga Operator.

## Getting started

- [Development guide](docs/site/contributing/development.md): local setup, build, tests, and e2e.
- [Documentation guide](docs/site/contributing/documentation.md): editing and previewing the docs site.
- Published docs: https://tsuga-dev.github.io/tsuga-operator/

## Pull requests

- Run `make lint test` before opening a pull request.
- Use conventional commit messages with a scope, for example `fix(controller): Patch finalizers instead of updating the whole object`. Common types: `feat`, `fix`, `refactor`, `test`, `chore`, `docs`.
- Keep changes focused and describe what changed and why.

## Bugs and security issues

Report bugs with the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md). Do not report security vulnerabilities in public issues; follow [SECURITY.md](SECURITY.md) instead.
